RecruitAI ATS — UI Field Validation Specification

Every user-editable field across the application, with its rule (mandatory/optional, length, allowed format), the expected validation message, and where the rule is actually enforced today. Fields with no validation are flagged as gaps to test and close.

Scope: Recruiter dashboard (React/TS) + Spring Boot API      Areas: 11      Method: source audit — client forms & server constraints

How to read the “Enforced” column

Both = validated on client & server      Client = browser/JS only (bypassable via API)      Server = API only (no inline UI feedback)      Gap = not validated anywhere (message is a recommendation)

Mandatory blocks submit when empty      Optional may be left blank      REC = recommended, not yet implemented

!  Known gaps & inconsistencies to test

Client ↔ server mismatches (surface as confusing errors)


Job · Department length: UI accepts up to 60 characters, but the API rejects anything over 50 (@Size(max=50)). A 51–60 char department passes the form and fails on save — align both to one limit.


Edit-Candidate modal email: the Add/Edit modal validates email with a regex, but the secondary Edit modal does not — an invalid email can be saved from one screen and not the other.


Resume errors return different codes: the same parse/cooldown failure is 400 via ResumeController but an uncaught 500 via IngestionController.


createCandidate error shape differs: it returns {errors:[…]} while every other @Valid endpoint returns {details:{…}} — tests asserting one shape miss the other.

Missing validations worth adding (currently “Gap”)


Dates in the past: the Meeting Scheduler date has no min; Schedule-Interview date isn&apos;t restricted to the future. Interviews can be booked in the past.


Number fields (Experience, Notice): enforce only min=0 in HTML — no upper bound, no JS check; out-of-range values post fine via API.


Free-text fields have no max length: across Candidate, Company and note/remark fields — recommend server-side @Size caps to prevent oversized documents.


Silent required fields: Add-Note and the LinkedIn message block Save when empty but show no message — add an inline hint.


Company logo & profile photo (server): only the 10 MB multipart cap applies; no image-type check server-side.


Grounded in a source audit of the recruiter dashboard (React/TypeScript) and the Spring Boot API. “Expected message” quotes the exact string in code where present; entries marked REC are recommended rules not yet implemented. Length/format values without a code citation are recommendations for the QA baseline.
